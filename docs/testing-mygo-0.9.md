# MyGo v0.9.0 macOS 实机验收

测试日期：2026-11-13。源码基线：`39007b1f9c54e5c2b1b744896d60d175f49640e7`（PR #10）。

桌宠窗口、素材包管理和设置恢复路径在本轮检查中可用。**本轮尚不能作为正式发布验收通过的依据**：naiwa 运行时 RSS 部分场景超过规格目标，Windows 与若干真机项目尚未覆盖。原始基线中的桌宠位置恢复失败已在后续工作区修改中修复并实机复测，见[回归复测](#位置恢复修复后的回归复测)。

## 性能观测

CPU 使用进程累计 CPU 时间的差值除以实际采样间隔计算，100% 表示一个逻辑核。RSS 来自 `ps` 的 KiB 值，除以 1024 换算为 MiB，**不等于 macOS physical footprint 或 Go heap**。目标以[桌宠规格的性能要求](specs/desktop-pet.md#性能观测)为准。

| 场景 | 样本数 | 平均 CPU | 采样窗口内最大 CPU | RSS 范围（MiB） |
|---|---:|---:|---:|---:|
| 鲸鱼短基线 | 10 | 6.25% | 7.46% | 175.64–175.78 |
| naiwa 清醒 | 15 | 4.54% | 6.97% | 250.39–250.56 |
| naiwa 困倦 | 44 | 5.94% | 8.44% | 322.91–323.06 |
| naiwa 睡眠阶段 | 11 | 0.00% | 0.00% | 320.73–321.06 |
| 补测：清醒、隐藏前 | 4 | 5.96% | 7.45% | 252.09–252.12 |
| 补测：隐藏宠物并关闭控制台 | 8 | 0.00% | 0.00% | 251.72–252.41 |
| naiwa“肚肚挑衅”动作 | 10 | 11.66% | 20.79% | 330.66–330.91 |

本轮所采样的清醒、动作、睡眠及隐藏 CPU 达到对应目标；没有测量低于采样间隔的瞬时峰值。2026-11-13 项目所有者将内存上限由 200 MB 放宽，并暂缓内存优化；当前上限以[规格](specs/desktop-pet.md#性能观测)为准。**naiwa 清醒约 250 MiB，困倦、睡眠与动作约 321–331 MiB；后几组仍超过新的 300 MB 上限**，不能把放宽指标标为全部达标。本次位置修复未重测性能，这些仍是原始基线的观测。后续分析应区分 Go heap 与图形资源，不能直接归因于某一类缓存。

CLI 导入也实际复测：退出测试应用后，用同一基线编译的 `petpack -zip … -data …` 导入到隔离目录，约 8.07 秒，`/usr/bin/time -l` 报告峰值 RSS 为 51,888,128 字节（约 49.48 MiB）。这与桌宠运行时驻留内存是两个指标。

补充启动计时：从启动新进程到首个桌宠窗口被窗口服务器列为可见，鲸鱼约 273 ms，naiwa 约 509 ms；文件缓存未清空。这不是海报完成绘制的精确计时，规格中的海报 <150 ms 目标尚未验收通过。

### 原始数据与筛选口径

- [鲸鱼短基线](references/mygo-0.9-acceptance-20261113/whale-baseline.csv)：20 秒，2 秒间隔，全部 10 个样本。
- [naiwa 静置序列](references/mygo-0.9-acceptance-20261113/naiwa-idle-sleep.csv)：2 秒间隔；进程于 `2026-11-13T08:21:37Z` 启动。为避开状态切换，清醒取进程年龄 20–50 秒，困倦取 75–165 秒，睡眠取 ≥195 秒。阶段名称根据规格时序推断，没有加入状态日志。
- 静置序列只使用 `elapsed_s ≤ 198` 的记录；最后约 12 秒已开始后续隐藏操作，保留在原始 CSV 中供核对，但不参与上表静置统计。
- [隐藏前的清醒基线](references/mygo-0.9-acceptance-20261113/naiwa-awake-before-hide.csv)：新进程运行约 23 秒后采集 8 秒，2 秒间隔；随后隐藏桌宠并关闭控制台。
- [清醒后隐藏](references/mygo-0.9-acceptance-20261113/naiwa-awake-hidden.csv)：确认没有可见测试窗口后采集 18 秒，2 秒间隔，表中取 `elapsed_s ≥ 4`。
- [特殊动作](references/mygo-0.9-acceptance-20261113/naiwa-action.csv)：1 秒间隔，共采集 16 秒；表中取 `2 ≤ elapsed_s ≤ 12`。

较早的一次“睡眠后隐藏”采样中控制台仍显示，未用于上述清醒隐藏结论。各组并非完全相同的进程历史，不能把组间 RSS 差值当作释放量或泄漏量。

## 位置恢复修复后的回归复测

2026-11-13，在基线 `39007b1` 加当前工作区的位置修复上重新打包。仍使用前述 macOS、单屏和工具链；应用名改为 `Lucia Position QA oMIulc`、独立 identifier 与数据目录，更新关闭。测试未触碰正式版或开发版设置。

根因与本地规避由[上游问题记录](upstream-mygo.md#6-固定大小-panel-的窗口状态保存)维护。修改前的隔离构建实际拖到 `(700, 330)`，退出后仍只有 `main` 状态；修改后的同一操作得到如下结果：

| 操作 | 原生复测结果 |
|---|---|
| 实际鼠标拖动 → 系统退出请求 → 重启 | 248×248 DIP 窗口从 `(700, 330)` 原位恢复；文件中的 `pet` 与窗口边界一致，`main` 同时保留 |
| 四档尺寸切换 | 198、248、310、372 DIP，底边中点保持 `(824, 578)` |
| 大尺寸 → 应用菜单退出 → 重启 | 310×310 DIP 窗口保持 `(669, 268)` |
| 隐藏 → 菜单退出 → 重启 → 显示 | 启动时保持隐藏，显示后仍为 `(669, 268, 310, 310)` |
| 连续三次正常退出与重启 | 坐标、尺寸保持一致，未再发生逐次上移 |

已检查恢复后窗口截图。测试实例全部退出。临时构建、日志、修改前探针与窗口记录在 `/tmp/lucia-position-fix.oMIulc/`；长期复现步骤为：拖至远离边缘处，记录坐标，正常退出并核对 `window-state.json` 的 `pet`，重启后核对边界；再分别覆盖大尺寸和隐藏状态。

新增存储层测试覆盖框架旧快照覆盖、桌宠先关闭再保存控制台、退出前没有框架脏状态、重新加载及 `App.ClearWindowStates` 清空后退出。新执行的 `CGO_ENABLED=0 go test ./...`、`go test -race ./cmd/lucia`、`go vet ./...`、`go tool mygo vet .` 与 Windows/amd64 交叉编译均通过；macOS 原生应用已打包运行。扫描了两个 `StateKey` 窗口及两处按最大化标志恢复的路径：桌宠已处理，控制台可调整大小、使用普通框架采集；气泡无 key，无需保存位置。

该复测只确认 macOS 当前环境中的位置修复；跨屏、Windows 与 Reduce Motion 的未覆盖范围仍保留在下节。2026-11-14 已补测 MyGo v0.9.0 的 macOS 真实自动升级，结果见[更新测试指南](testing-updates.md#本轮演练mygo-v0902026-11-14)。

## 未覆盖项与后续复测

- **Windows 真机（本阶段跳过）**：2026-11-13 项目所有者明确选择跳过，后续工作不再等待此项验收。当前 Windows 证据为 CI、交叉编译与打包；透明窗口、拖动、高 DPI 和设置备份文件覆盖行为仍未实测。
- **跨屏与 Space 切换**：本轮只有一块显示器，没有验证跨屏拖动、不同缩放显示器及其他全屏应用。
- **Reduce Motion 原生行为**：系统设置保持关闭，没有实际切换；已有无窗口测试覆盖，真机项目仍待补测。
- **音效与清晰度对照**：没有做真实声卡试听，也没有并排运行旧版比较图像清晰度。
- **延迟与长时间稳定性**：没有精确测量点击到首帧、海报绘制完成时间或连续数小时运行。
