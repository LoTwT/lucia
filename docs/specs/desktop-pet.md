# 桌宠 Happy Path（增量 A/B/C）

更新日期：2026-10-20。本文维护桌宠窗口、常驻生命周期、idle 行为、点击互动与气泡的单一事实来源；模块关系见 [architecture.md](../architecture.md)，素材授权见 [NOTICE.md](../../internal/pet/assets/deepseek-whale/NOTICE.md)。

## 目标

启动后直接出现一只透明、无边框、置顶的桌宠。它可以拖动，有 idle 呼吸和眨眼，位置在重启后恢复；点击脸部会做出压扁回弹反应，右键菜单也能触发同一反应；摸脸和摸摸头会在宠物上方显示不同台词，2.6 秒后消失；托盘可以显示或隐藏它、打开 Lucia 控制台并退出应用。

## 窗口形态

| 选项 | 值 |
|---|---|
| 尺寸 | 248×248 DIP，立绘 240×240 居中，留出呼吸位移的边距 |
| `Frameless` / `Transparent` | `true`，窗口本身没有标题栏和底色 |
| `AlwaysOnTop` / `Panel` | `true`，浮在其他应用之上，不抢当前应用的焦点 |
| `SkipTaskbar` / `DisableShadow` | `true`，不占任务栏，不出现矩形窗口阴影 |
| 固定形态 | `DisableResize`、`DisableMinimize`、`DisableMaximize`、`DisableFullScreen` 均为 `true` |
| 位置 | `StateKey: "pet"`；首次出现在主屏工作区右下角，距边缘 24 DIP |

视图根节点使用透明背景，立绘以 `ui.Image` 绘制。窗口本身是 `DragWindow` 手柄，拖动立绘的主体或尾巴移动窗口；脸部另有一个透明点击区域，点击它触发互动。透明边距不额外扩大窗口。

## 窗口位置约束

拖动和恢复使用两套时机，避免把“跨显示器”误判成“拖出屏幕”：

- 拖动由系统原生 `DragWindow` 完成。它在两块显示器之间移动时由系统接管，不会出现自绘 `SetPosition` 触发的吸附和来回跳动。
- 原生拖动允许宠物短暂越过屏幕边缘。`Window.OnMove` 发现窗口落在有效区域外时开始观察，等主键松开后再按下面的规则收回；macOS 用 `NSEvent.pressedMouseButtons` 查询按键状态，因此按住不放不会被打断。Windows/Linux 暂无对应的 MyGo 接口，暂以 300 ms 稳定延迟代替。
- 恢复时，窗口完整落在一个显示器的工作区内就不动；横跨两块显示器且完整落在物理范围并集内时保留；其余位置按最小位移收回到最近的显示器工作区。工作区排除了菜单栏、Dock 和任务栏。
- 启动和显示器变化也走恢复路径：先撤销意外的最大化、恢复固定尺寸，再按同一规则恢复位置。这样拔掉外接显示器或修改分辨率后，旧位置不会把宠物留在不可达区域。

## 点击互动

- 脸部点击区位于立绘上方中央，约 60×64 DIP；点击它触发 450 ms 的压扁—回弹动画，底部保持不动。
- 脸部点击区不承担拖动；拖动身体、尾巴或窗口其他区域移动宠物。这是 MyGo v0.5.5 中 `DragWindow` 与 `OnClick` 不能落在同一元素上的直接结果。
- 右键任意宠物区域打开上下文菜单，菜单项“摸摸头”触发同一反应。
- 点击互动只改变视图内的缩放，不移动窗口，也不会打断系统拖动。

## 气泡

- 气泡是独立的透明 Panel 窗口，固定 240×92 DIP；不设 `StateKey`，不写入窗口位置。
- 整窗调用 `SetIgnoreMouseEvents(true)`，所有点击穿透到下面的应用，不扩大宠物的矩形命中区。
- 摸脸和摸摸头各自维护一组台词，按顺序循环；未知反应不显示。
- 气泡优先显示在宠物上方，间距 8 DIP；上方放不下时翻到下方；水平位置限制在当前显示器工作区内。
- 显示使用 `ShowInactive`，不抢当前应用的焦点；2.6 秒后自动隐藏。
- 设置里的气泡冷却会跳过冷却期内的后续气泡；选择“关闭”时只保留动作和音效。
- 宠物开始移动、被托盘隐藏或应用退出时立即隐藏气泡；拖动中不跟随宠物。
- 气泡内容与定位由 `internal/pet` 的纯模型和测试覆盖，窗口生命周期由 `cmd/lucia/bubble_window.go` 管理。

## 生命周期

- 主窗口（Lucia 控制台）启动时隐藏，由托盘“打开 Lucia”、第二实例或 `lucia://` 深链接打开。
- 关闭桌宠窗口、气泡窗口或控制台窗口只隐藏窗口，不退出进程。
- `OnWindowAllClosed` 保留为空实现；只有托盘“退出”或 Cmd+Q 结束进程。
- `OnBeforeQuit` 设置退出标记，各窗口的 `OnClose` 在退出时放行，平时阻止关闭并隐藏。
- `OnActivate` 只在没有任何可见窗口时打开控制台；桌宠可见时，点击 Dock 图标不会突然弹出控制台。
- 托盘提供“显示/隐藏宠物”“重置宠物位置”“打开 Lucia”“退出”四项。
- 控制台“桌宠”卡片提供显示桌宠、开机自启和重置位置。

## 设置

- `settings.json` 新增 `petVisible`、`soundEnabled` 和 `bubbleCooldownSeconds`。`petVisible` 默认 `true`，`soundEnabled` 默认 `false`，`bubbleCooldownSeconds` 默认 `0`（每次互动）；加载时先取默认值再合并文件，旧配置缺少字段时保留这些默认值。
- 托盘显示/隐藏宠物会立即保存可见性；下次启动创建宠物窗口时直接使用该状态，隐藏状态不会闪一下再消失。
- 控制台“显示桌宠”开关与托盘共享同一份状态；隐藏或显示都会同步控制台模型。
- “互动音效”默认关闭；开启后摸脸和摸摸头播放 `cmd/lucia/pet_sound.go` 在内存中生成的双音短提示音，不引入第三方音频素材。
- “气泡频率”提供“每次互动 / 最多每 30 秒 / 最多每 2 分钟 / 关闭”。冷却只限制气泡显示，不影响动作和音效。
- 开机自启由 MyGo 的登录项接口读写，控制台显示系统当前状态；不使用 `settings.json` 复制一份可能失真的值。开发构建或未打包运行时如果系统拒绝，设置页显示错误。
- “重置宠物位置”把宠物移回主屏工作区右下角，距边缘 24 DIP，并重新显示宠物。

## Idle 行为

- 使用三帧透明 PNG：睁眼、半闭眼、闭眼。
- 4 秒一个周期，3.8 秒开始眨眼；半闭 60 ms、闭眼 90 ms、再半闭 60 ms，然后回到睁眼。
- 立绘以 3.2 秒周期上下浮动 2.5 DIP，窗口位置不动，避免与系统拖动冲突。
- 距上次互动 60 秒后进入困倦，固定使用半闭眼帧；3 分钟后睡着，固定使用闭眼帧。摸脸、摸摸头和拖动都会唤醒。
- 摸脸是 450 ms 的压扁回弹；摸摸头是 620 ms、幅度更小并带轻微上抬，两者无需额外素材即可区分。
- 动画时钟取自 `ui.Context.Now()`，每帧调用 `c.AnimationFrame()`；状态由时钟推导，不使用 goroutine、ticker 或后台计时器。
- 素材在包初始化时用 `//go:embed` 嵌入并只解码一次；视图测试不依赖磁盘文件。

## 非目标

本增量包含独立气泡，但不包含桌面走动、物理/吸附、AI 对话、设置页、换肤、多只宠物和 Windows 专项验收。这些在 A/B/C 稳定后按增量推进。

## 验收

自动检查：

```sh
gofmt -l .
go vet ./...
go test ./...
go tool mygo vet .
```

`internal/pet` 的视图测试覆盖素材解码、眨眼帧选择、点击反应曲线、脸部点击区、身体拖动区、右键菜单、透明根节点、可见像素、动画请求、托盘图标尺寸、气泡台词循环、气泡视图和上下/边界定位。

macOS 真机手工检查：

- 启动后只见桌宠，不见控制台；控制台可从托盘打开。
- 窗口无白底、无矩形阴影，始终置顶。
- 点击脸部有压扁回弹反应；点击/拖动身体可以移动窗口。
- 右键菜单出现“摸摸头”，选择后有同样反应。
- 点击脸部和摸摸头出现不同气泡台词，动作幅度和时长也不同；2.6 秒后自动消失。
- 气泡不接收鼠标，靠近屏幕顶部时翻到宠物下方；拖动宠物或从托盘隐藏宠物时立即消失。
- 点击桌宠不会把当前应用切走，气泡显示也不会抢焦点。
- 托盘隐藏宠物后重启，宠物保持隐藏；托盘“重置宠物位置”会重新显示并回到右下角。
- 控制台“显示桌宠”与托盘状态一致；打包构建中开机自启开关能读写系统登录项。
- 开启“互动音效”后摸脸和摸摸头各有一次轻短提示音；关闭后完全静音。
- 气泡频率切到“最多每 30 秒”后连续摸两次只出现第一句气泡，动作和音效仍正常；切到“关闭”后不再出现气泡。
- 拖到屏幕边缘继续拖时允许短暂越界，松手后回到工作区内并仍然可拖动。
- 在多显示器交界处拖动保持平滑，不出现来回跳动；拔掉外接显示器后窗口回到可用工作区。
- 重启后位置恢复；隐藏/显示和退出都从托盘完成。
- 关闭桌宠或控制台只隐藏，进程继续运行；托盘“退出”真正结束。

Windows 的透明分层窗口、任务栏隐藏和托盘行为留到第二个平台补验。

显示器移除、工作区变化由 `KeepOnScreen` 的纯几何测试覆盖；物理拔插外接显示器或修改分辨率仍需双屏真机验收。

## 性能观测

2026-10-20 在 Apple M1 Pro、内置 1512×982 与外接 2560×1440 双屏、开发构建下测得：桌宠可见且空闲时，`top` 采样 `%CPU` 约 16–19%，常驻内存约 78–142 MB。当前 `View` 每帧调用 `AnimationFrame()`，会按显示刷新率持续重绘；这是 G 阶段桌面行为之前的基线，不代表最终性能预算，也尚未拆分 GPU 占用。若后续增加走动或更多动画，应先把空闲重绘频率纳入优化评估。

## 风险与回退

`Panel + Transparent` 的原生 UI 如果出现不透明底色、拖拽异常或焦点被抢，回退为普通 `Frameless + Transparent + AlwaysOnTop + SkipTaskbar` 窗口，并接受“点击会激活应用、可能不覆盖全屏”的代价。透明窗口的整窗命中无法只让非透明像素接收鼠标，因此宠物窗口保持贴合立绘，气泡使用独立窗口并整窗穿透。

拖动结束的检测目前只在 macOS 读取 `NSEvent.pressedMouseButtons`；如果以后要完全自绘拖动或支持其他平台，应由 MyGo 上游提供拖动结束回调或窗口约束覆盖，而不是在拖动过程中反复 `SetPosition`。
